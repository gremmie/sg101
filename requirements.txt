# SG101 runtime requirements -- Python 3.12 / Django 5.2 LTS.
#
# This file is what the prod image installs, and requirements_dev.txt follows
# through `-r requirements.txt` for the dev image.
#
# django-elsewhere used to be an editable git dependency; it's now vendored into
# the repo (the fork is tiny and frozen upstream, and needed Py3 patches), so it
# no longer appears here.

Django==5.2.17
# 12-factor env-var config: base.py reads .env through this and every secret
# comes from it. The 0.4.5 pin it sat on was chosen in Step 3 as "the last line
# supporting Python 2.7" -- a constraint five interpreters stale by the time it
# moved. 0.14.0 also drops the pkgutil.find_loader() call that cost the
# deprecation gate an ignore.
django-environ==0.14.0
# The IANA timezone database, as a package. zoneinfo reads the *host's* tzdata
# and falls back to this package on sys.path; pytz bundled its own copy, so this
# only started mattering when the timezone code moved to zoneinfo. It is not
# optional here: the base image ships no "backward" names -- there is no
# /usr/share/zoneinfo/US at all -- and 12,619 of 15,227 profiles are stored as
# US/Pacific. Without this package they raise ZoneInfoNotFoundError out of a
# template tag. It was already being installed as a transitive dependency of
# kombu; it is pinned directly because nothing should make this site's timezone
# correctness a detail of the celery dependency graph.
tzdata==2026.3
# six is no longer imported by the application -- it uses the Python 3 standard
# library directly (urllib.parse/request/error, io.StringIO). It is still pulled
# in transitively, so the pin stays for a reproducible build: unpinning would not
# remove the package, only let it float, as a rebuild once demonstrated by
# drifting to 1.17.0.
#
# One requirer is left, down from four: python-dateutil, which celery requires --
# so six does not leave the image by dropping a pin here, and will not until
# dateutil stops needing it. bleach dropped six at 6.4.0, python-memcached left
# with the memcached cache, and html5lib was dropped as an orphan.
six==1.16.0
# sqlparse is a hard runtime dependency of Django as of 2.2 (used internally to
# split/format SQL). It installs automatically with Django; pinned here so the
# build stays reproducible. Django raised its floor to 0.3.1 at 4.2, so this is
# a real constraint now and not only a reproducibility pin.
sqlparse==0.5.5

# The uppercase settings compat is gone in celery 5, so the config moved to the
# CELERY_ namespace -- see sg101/celery.py and sg101/settings.
#
# The 5.2 line was held down by Python 3.7. What made moving it necessary rather
# than merely possible: kombu 5.2 reads its transport registry through
# entry_points().get(), and the standard library removed that dict interface in
# Python 3.12. That removal is now live -- this image runs 3.12 -- and these
# pins are what keep the broker transport resolvable, so a downgrade here does
# not degrade, it stops celery finding its transport at all.
celery==5.6.3
kombu==5.6.2
billiard==4.2.4
amqp==5.3.1
vine==5.1.0

# mysqlclient is NOT here for Django -- the site runs on PostgreSQL and nothing
# points the ORM back at MySQL. It is here because tools/pgloader/verify.py and
# verify_data.py import MySQLdb: they read the MySQL source and the converted
# PostgreSQL side by side to check that a conversion did not lose or shift
# anything. The mysql CLI loads the dump and pgloader does the converting;
# neither needs this driver, and only the verification does. Removing it would
# leave a conversion unverifiable rather than failing outright -- and since those
# tools are not part of the test suite, nothing would go red. That matters most
# at the production cutover, which converts a fresh snapshot under a maintenance
# window. The 1.4.x line has no wheel, so it builds from source; see the
# Dockerfile for the two apt packages that lets it.
mysqlclient==1.4.6
# psycopg2, not psycopg 3, and that is now a decision rather than a leftover:
# Django gained psycopg 3 support in 4.2, and this project looked at taking it
# and declined for the moment. The reason is that it would not be a swap. The
# three tools/pgloader/ scripts import psycopg2 directly and are what verify the
# production cutover, so psycopg2 stays in the image either way; adopting
# psycopg 3 means running two PostgreSQL drivers rather than a newer one. The
# gain is real but small for this site's load, and it keeps better than it
# spends: the next Django upgrade meets a psycopg 3 backend a release more
# settled, by which time the pgloader tools may have retired with the MySQL box
# and taken the second driver with them.
#
# Built from source (libpq-dev in the Dockerfile), not psycopg2-binary, which
# upstream discourages for anything but a quick trial. The old 2.9.9 pin dated
# from the Python 3.7 cap (2.9.10 requires 3.8+), which no longer binds.
psycopg2==2.9.12
# redis-py is the client for three things now: the application's own Redis use,
# the Celery broker transport, and Django's built-in Redis cache backend
# (which needs >= 3.0). No django-redis package is involved -- that backend
# has been part of Django since 4.0.
#
# It moved off 3.5.3 with celery/kombu, which is the only reason it moved at all.
# kombu's runtime guard only asks for >= 3.2.0, so 3.5.3 would not have raised;
# but kombu 5.6 does `from redis import CredentialProvider, sentinel` under one
# try/except, and on 3.5.3 the missing CredentialProvider took `sentinel` down
# with it -- silently, to None. kombu's own extra asks for >= 4.5.2, < 6.5.
redis==6.4.0

# Pillow 10 removed Image.ANTIALIAS, the resampling constant 7 call sites used;
# they now name Image.Resampling.LANCZOS, which is the same filter -- ANTIALIAS
# had been an alias for it, both enum value 1, so the rename cannot move a pixel
# and 13 thumbnail outputs stayed byte-identical across it.
#
# The whole PIL surface this project touches was diffed from 9.5.0 through
# 12.3.0 and is unchanged: the 5 transpose constants orient_image() names (which
# 9.4 un-deprecated), ImageFile.Parser, _getexif(), MAX_IMAGE_PIXELS, the JPEG /
# PNG / GIF / WebP round-trips, and UnidentifiedImageError still subclassing
# OSError so bio/forms.py's `except IOError` keeps catching it. Thumbnail output
# is byte-identical to 9.5.0 as well -- the drift measured over 6.2.2 -> 9.5.0
# did not recur.
#
# Wheels are manylinux and carry their own codecs, so the Dockerfile still needs
# no libjpeg/zlib headers; features.check('jpg') is what proves that per build.
Pillow==12.3.0
lxml==6.1.1
# bleach 3.1.5 could not import on Python 3.10 (it read Mapping out of
# collections), so it moved with the interpreter. 6.4.0 is the final release --
# upstream archived bleach in 2023 in favor of nh3 -- so this pin is at the end
# of the line rather than behind it.
bleach==6.4.0

Markdown==3.10.3
docutils==0.23

# repoze.timeago is deliberately NOT bumped: 0.5 is the last release and
# upstream stopped in 2011, so there is nothing to bump to. It is also the
# source of the one third-party ignore the deprecation gate still carries --
# its module-level `_NOW = datetime.utcnow`, deprecated in Python 3.12.
#
# What makes replacing it a decision rather than a swap is that it rounds to
# NEAREST and stops at days, and the obvious alternatives truncate and escalate:
# 90 seconds is "2 minutes ago" here and "1 minute ago" in both `timeago` and
# django.utils.timesince, and a 2015 post reads "3800 days ago" here. Those
# strings render on every forum topic and post listing, so any swap restyles the
# whole archive. (This last figure said "1 year ago" until 2026-09-03, when it
# was measured rather than recalled: timesince answers "10 years, 4 months ago".
# Only timesince was measured; the `timeago` package was not.)
#
# DECIDED 2026-09-03: replace it with django.utils.timesince, which is already in
# the stack -- so this is a deletion rather than a swap, and it takes the gate's
# last third-party ignore with it. Vendoring the 79 lines was the standing
# recommendation here, on the grounds that it changes no rendered string; the
# measurement is what reversed it. Not escalating past days means a 2015 post
# reads "3800 days ago", so preserving the display is the cost of vendoring
# rather than its benefit. The swap restyles every forum listing, which is why
# it waits for its own change rather than riding a dependency bump.
repoze.timeago==0.5
requests==2.34.2
